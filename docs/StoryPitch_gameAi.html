Memory Extraction Methods
▼
Automatic: AI returns "memory" JSON field → parsed via 9‑strategy parser → updates NPCs/locations/inventory/relationships instantly.
Manual Refresh: User clicks button → calls /refresh-memory → LLM analyzes last 3 narrations with build_memory_analysis_prompt → enriches all categories.
Example: "You meet Eldrin the wizard." → AI extracts NPC Eldrin (personality: wise, first_met_step: 5), Location: Wizard's Tower → stored.

Load Snapshot Integrity Logic
When loading a snapshot: restore world_state and current_step → delete the step at current_step (so player can make a different choice) → delete all steps with index > current_step → timeline remains linear, no parallel branches.

🤖 LLM Fallback Chain — Never Crashes
Three layers of resilience for story generation
1️⃣
Primary Model
▼
LM Studio (local) → uses /v1/chat/completions or /v1/completions, auto‑detects model. Timeout 300s, retries 2 times.
If LM Studio fails → moves to HuggingFace Inference API (online).
2️⃣
Fallback Model
▼
HuggingFace (configurable model, e.g., gpt2 or larger). Uses API key, 3 retries.
If HuggingFace also fails → triggers intelligent fallback generator.
3️⃣
Intelligent Fallback Generator
▼
Keyword‑based: detects "explore", "fight", "talk" in player action → returns themed narration + 4 choices. Includes FALLBACK_AI_TEXT from constants if no keyword matches.
Never returns empty string. Always provides valid narration and choices.
⚡ LLM caching: in‑memory TTL cache (300s) keyed by model+prompt SHA256. Reduces latency and cost.
